# Consuming the playbook from other skills and tasks

The playbook only pays for itself if the work that follows actually reads it. Conventions:

## Where it lives

Default location: `playbook.md` and `playbook-private.md`, alongside each other, one pair per principal. With multiple principals, use a folder per person (`principals/gc/playbook.md`).

Only `playbook.md` is read by AI assistants. The annex is referenced, never loaded.

## Reading it

Read the relevant sections, not the whole file, and read *before* drafting rather than after — a draft written first and corrected against the playbook afterwards keeps the wrong shape.

| Doing this | Read |
|---|---|
| Drafting as the principal | §5 Communication, §2 Professional preferences, plus the writing samples |
| Travel | §6 Travel, §3 Daily routine (for departure timing), §9 emergency procedure |
| Diary decisions | §4 Scheduling, §3 Daily routine, §7 for who the requester is |
| Briefing packs | §2 Work profile, §7 Key relationships |
| Hospitality, gifts, food | §8 Preferences |
| Anything touching press or sensitive documents | §11 Confidentiality |

## Honouring the tags

- `[said]` — act on it directly.
- `[observed]` — act on it, but if the stakes are high, verify. "The playbook has this as observed rather than confirmed — worth a quick check?"
- `[inherited]` — treat as a hypothesis. Especially for anything a previous assistant recorded more than a year ago.

## Gaps

When the playbook doesn't cover something, **say so and ask** — do not fill the gap with a plausible default. A playbook that quietly accumulates invented preferences is worse than no playbook, because it's trusted.

Then add the gap to the file as `— not yet known`, so it's visible next time.

## Corrections

When the principal corrects something the playbook got wrong, that correction is the most valuable input the playbook ever receives. Update the line the same day, retag it `[said]`, and date it. Do not wait for the quarterly review.

## What never leaves the playbook

The operating file is safe to read. The annex is not, and no task should request it. If a task appears to need annex material — a passport number for a booking, a home address for a delivery — hand the task back to the assistant to complete manually rather than pulling the annex into context.
